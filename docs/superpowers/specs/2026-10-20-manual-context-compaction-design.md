# 手动压缩上下文设计

## 目标

让用户在长对话中主动总结较早的消息，并继续在原对话中交流。压缩后，完整原始消息仍保存在历史记录并可在页面查看；后续模型请求以摘要和摘要之后的消息作为上下文，从而释放上下文窗口。

## 推荐方案

沿用本项目现有的总结生成、消息持久化、上下文用量和 token 记账机制，增加一种只执行总结的内部聊天轮次。前端在上下文用量弹窗提供“压缩上下文”操作；后端基于当前活动分支的末端生成摘要，将其保存为特殊 summary 内容，并让后续上下文构建从该摘要边界继续。

不直接合并上游整套提交。上游实现提交涉及多处请求、流式恢复、历史持久化和依赖版本变更；本项目已有自定义的聊天、Agent 和额度链路，应按本地代码边界移植等价行为。

## 适用范围

- 支持本地保存并组装历史记录的普通聊天和 Agent 对话。
- 暂不支持 Assistants 等由外部服务管理对话历史的端点。
- 只允许压缩当前用户有权访问的已存在对话和活动分支；新对话、临时状态未落库的对话和正在生成的对话不可压缩。
- 功能沿用部署级总结开关。服务器未启用总结时，前端不展示操作，后端也拒绝手工构造的压缩请求。

## 用户行为

- 用户从现有上下文用量入口打开详情并选择“压缩上下文”。
- 请求提交后显示压缩中状态；压缩过程不创建新的用户消息，也不把编辑框中未发送的文本、文件或待处理技能选择并入摘要。
- 完成后，摘要出现在当前分支末端。用户继续发送消息时仍留在同一对话。
- 原始消息不删除。上下文空间来自模型不再接收摘要以前的完整消息，而不是删除聊天记录。
- 用户可以在摘要之后继续聊天；累积新消息后可以再次压缩。

## 请求与后端处理

- 客户端沿用现有聊天提交和流式响应通道，发送明确的 `compact: true` 标记，并把当前活动分支的末端消息作为锚点。
- 服务端验证用户身份、对话所有权、活动分支锚点、总结功能开关及生成状态。锚点必须属于请求用户和该对话，不能仅信任客户端传入的消息 ID。
- 压缩轮次只运行总结步骤，不生成普通回答，也不触发依赖新用户消息的记忆写入、标题生成或其他用户轮次副作用。
- 总结成功后以普通响应持久化通道写入 summary 内容，并保存后续上下文用量计算所需的摘要 token 基线。
- 总结失败、被中断或没有产出摘要时，不改变已保存的原始历史；客户端收到可本地化的错误，并可在会话恢复空闲后重试。
- 已经是未追加新消息的摘要末端时，禁用重复压缩；必须有新的对话内容后才能再次压缩。

## 存储、上下文与隔离

- 原始用户和助手消息保持不变，摘要作为当前分支上的新 summary 内容保存。
- 历史显示仍能读取原始消息；模型侧上下文构建识别最近一次有效摘要，并将其作为较早对话的替代上下文，同时保留摘要之后的消息。
- 分支压缩仅作用于用户当前选择的活动分支，不改写其他分支。
- 所有历史读取、摘要生成和消息保存均继续使用已认证用户身份；不得跨用户复用摘要或工作状态。

## 用量与错误处理

- 手动总结会额外调用一次总结模型，必须走现有 token、费用和额度记录链路，按实际 provider、model 和 usage 记录一次。
- 总结调用的费用与后续正常回复分开核算，避免遗漏、重复计费或把总结 token 错算为用户可见的普通回答内容。
- 总结关闭、找不到锚点、锚点不是活动分支末端、上下文已被压缩、没有可总结内容和总结服务失败均返回稳定错误类型，由客户端显示本地化提示。
- 即使请求因系统指令本身过长而无法总结，也保留完整历史并向用户说明无法压缩；压缩不改变模型窗口大小或系统指令长度。

## 本地实现边界

- 客户端：扩展 `client/src/components/Chat/Input/TokenUsage/`，增加操作入口和压缩状态；在聊天提交层支持内部压缩请求；新增所需的英文 locale 文案，并遵守项目现有中文翻译流程。
- 共享协议：在 `packages/data-provider` 定义压缩请求标记、启动配置能力字段及错误类型，保持客户端和服务端协议一致。
- 服务端：在现有 Agent 请求和 BaseClient 历史处理链路增加最薄的路由适配；可复用的校验和压缩状态逻辑放在 `packages/api`，优先复用已存在的总结、摘要内容和用量记录实现。
- 部署配置：使用现有总结开关控制能力；启动配置只向客户端公开是否可用，不暴露服务端密钥或模型凭据。

## 验收标准

1. 已有且空闲的本地历史对话可从上下文用量弹窗发起压缩；新对话、生成中对话和 Assistants 对话不可发起。
2. 成功后不产生用户消息气泡，不另建会话；摘要挂在正确的当前分支末端，原始消息仍可查看。
3. 压缩后的下一轮模型上下文包含摘要和摘要后的消息，不再包含摘要之前的完整原文。
4. 其他用户不能通过伪造 conversationId 或 messageId 压缩、读取或修改目标会话。
5. 总结调用按实际 token 用量进入现有记账链路且只记一次；上下文用量显示不重复累计被摘要替代的旧消息。
6. 失败和中断不破坏原始历史，错误提示可理解，恢复后允许重试。
7. 覆盖请求校验、分支锚点、总结持久化、压缩后的上下文构建、用量核算和前端可用状态的自动化测试。

## 不在本次范围

- 不自动创建新对话或把摘要复制到另一条对话。
- 不删除、隐藏或改写旧消息。
- 不承诺摘要逐字保留历史细节，也不以此增加模型的最大上下文长度。
- 不支持外部托管历史的 Assistants 端点。
- 不改变现有自动总结触发策略、模型选择策略或部署的用户隔离方式。
