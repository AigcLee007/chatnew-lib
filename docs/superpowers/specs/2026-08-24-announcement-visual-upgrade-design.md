# 公告视觉与交互升级设计

## 目标

让现有公告功能达到参考截图的使用体验：登录用户发现未读公告时自动看到居中的公告弹窗；用户可以从右上角公告入口打开公告中心；公告入口通过红点提示未读状态；用户确认公告后红点消失。

## 现有基础

- `NoticePopover` 已负责右上角公告入口、公告列表和红点。
- `NoticeModal` 已负责公告详情弹窗。
- `createNoticeSlice` 已负责公告加载、详情状态和当前的 `localStorage` 已读标记。
- `announcement.json` 目前为空，公告实际由现有 API 返回。
- 本次只调整公告展示和已读交互，不改管理员发布字段和现有公告 API 路径。

## 交互设计

### 自动公告弹窗

当公告加载后检测到未读公告，自动打开当前最新的公告详情弹窗。弹窗显示在页面中央，背景使用半透明遮罩和轻微背景模糊，阻止用户误操作底层聊天界面。

弹窗包含公告图标、标题、发布时间、正文、右上角关闭按钮和底部主按钮“我知道了”。点击关闭按钮或主按钮都视为确认当前公告，并移除红点。确认失败时保留本地未读状态，下一次加载仍可提示。

同一公告在当前会话中只自动弹出一次；用户从公告中心再次点击公告时仍可手动查看详情，但不会重复触发自动弹窗。

### 公告中心

右上角公告按钮保持现有入口位置和铃铛图标。存在未读公告时显示红色小圆点；按钮本身不因未读状态持续跳动，避免干扰聊天操作。

点击入口打开右对齐的公告中心面板，面板包含：

- “通知公告中心”标题和公告图标。
- “标注已读”快捷操作。
- 可滚动公告列表。
- 每条公告的标题、日期、两行摘要和置顶状态。
- 空状态提示。

点击列表项关闭公告中心并打开详情弹窗。详情弹窗关闭后，当前公告被标记为已读。

### 已读状态

继续沿用当前 `lastReadNoticeId` 的兼容逻辑作为本地回退方案。已读状态的更新集中在 store action 中，组件只触发“打开详情”和“确认关闭”动作，避免出现弹窗和列表分别维护红点的情况。

当公告列表刷新并发现最新公告 ID 与本地已读 ID 不同时设置红点并允许自动弹窗。点击“标注已读”将当前列表中的最新公告设为已读并立即移除红点。

## 视觉设计

- 详情弹窗最大宽度约 `450px`，桌面端保持截图中的紧凑比例。
- 弹窗使用项目现有 `bg-card`、`border-border`、`text-foreground` 等主题变量，同时适配浅色和深色模式。
- 遮罩使用 `bg-black/60`，配合 `backdrop-blur-md`，层级高于聊天内容。
- 公告图标使用 `Megaphone`，图标区域使用浅色主题背景和圆角容器。
- 内容区域使用独立的浅色背景、边框和圆角，正文保留换行。
- “我知道了”使用全宽主按钮，桌面和移动端都保证可点击区域不小于 44px。
- 公告中心宽度在桌面端约 `320px`，移动端改为左右留白的底部或全宽面板，避免超出视口。
- 关闭按钮、公告入口和“标注已读”均提供可访问标签或明确标题。

## 状态与错误处理

- 未认证或公告请求失败时不自动弹窗，不清空已有可用公告列表。
- 详情确认请求或本地状态更新失败时保留红点，并允许用户再次确认。
- 自动弹窗只针对最新未读公告，列表中的其他未读公告仍显示未读状态。
- 打开公告中心不直接清除红点；只有“我知道了”或“标注已读”才清除红点，符合参考图中的明确确认动作。
- 保留现有管理员公告发布、编辑、启用/停用和删除能力。

## 测试范围

- store：未读判断、确认关闭、标注已读和失败保留红点。
- `NoticePopover`：红点、列表打开、点击公告进入详情、空状态和标注已读。
- `NoticeModal`：自动弹出、遮罩、关闭按钮、确认按钮和移动端布局基础断言。
- 构建和 lint：确认 TypeScript、Vite 构建及 ESLint 通过。

- 不改公告 API 的 URL、字段命名或服务端存储结构。
- 不把参考截图中的品牌名、公告正文或模型名称写入项目。
