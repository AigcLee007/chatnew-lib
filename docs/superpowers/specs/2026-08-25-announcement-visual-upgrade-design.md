# 新仓库公告视觉升级设计

## 目标

让 `chatnew-lib` 的公告体验达到已确认示意：有新的或未读公告时，公告入口显示红点并自动打开公告详情；用户点击公告入口打开公告列表时，立即把当前可见未读公告标记为已读并移除红点。

## 现状与范围

- 后端已经通过 `/api/announcements` 返回 `unread` 字段，并通过 `POST /api/announcements/read` 持久化用户已读状态。
- 前端已有 `AnnouncementPopover`、红点、自动打开和批量已读基础逻辑。
- 本次只增强新仓库现有 LibreChat 结构，不迁移旧项目根目录组件，不覆盖新仓库已有功能。
- 管理员公告发布、编辑、停用、删除流程保持不变。

## 交互设计

1. 登录用户加载公告后，如果出现新的未读公告，公告入口保留红点，并打开公告详情层，显示置顶标记、标题、正文和确认按钮。
2. 点击确认、关闭按钮、Escape，关闭详情层并提交当前未读公告的已读状态。
3. 点击公告入口打开公告列表时，立即提交当前未读公告的已读状态；请求成功后入口红点消失，列表中的项目同步变为已读。
4. 已读请求失败时保留红点，用户下一次打开列表或窗口重新获得焦点时重试。
5. 多次刷新并发返回时只应用最后一次列表响应；旧请求不能覆盖较新的未读状态。
6. 新公告在已读请求进行期间到达时，不能被旧请求错误清除，必须继续显示红点并在下一轮请求中标记。

## 组件与数据流

- `AnnouncementPopover` 继续负责公告入口、列表、管理员操作和请求协调。
- 新增轻量公告详情层，复用现有 Tailwind/Portal 样式和可访问性模式；它只接收当前未读公告列表、关闭回调和已读回调。
- `itemsRef` 保存请求协调所需的最新列表；React state 负责渲染。
- 已读接口一次提交公告 ID 数组，成功后仅更新提交时仍存在的对应项目；不会清除提交后新到达公告的 `unread` 状态。

## 错误与可访问性

- 网络或非 2xx 响应不清除红点，也不阻塞公告列表继续打开。
- 详情层使用 `role="dialog"`、标题关联、明确的关闭按钮和 Escape 关闭；打开时焦点进入弹窗，关闭后恢复到公告入口。
- 移动端详情层和列表限制最大高度并独立滚动，不能撑破视口。

## 验证

- 前端组件测试覆盖自动详情层、入口红点、打开列表即已读、失败重试、并发响应保护和新公告保留。
- 运行公告组件测试、相关 API 测试和客户端构建；最后运行格式检查与 `git diff --check`。
