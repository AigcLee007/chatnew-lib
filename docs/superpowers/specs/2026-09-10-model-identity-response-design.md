# 模型身份确定性回答设计

## 背景

用户从模型菜单选择模型后，询问“你是什么模型”一类问题时，上游模型可能根据自身系统提示词或网关映射错误地回答为 Codex、GPT-5 或其他模型。LibreChat 当前的 `model` 参数只负责请求路由，不能保证模型的自然语言自报身份准确。

当前模型通过普通聊天的 `AgentClient`/`BaseClient` 发送。自定义 OpenAI 兼容端点在 `librechat.yaml` 中声明模型列表，但 `fetch: false` 只控制模型展示，不验证网关是否真的支持对应模型。因此身份回答必须由 LibreChat 根据本次请求的端点和模型确定。

## 目标

- 用户明确询问当前模型身份时，返回与当前选择一致的固定文案。
- 文案中的厂商来自当前端点配置，模型名称来自当前请求的模型 ID 或已知显示名称。
- 覆盖中文和常见英文身份询问。
- 非身份问题、模型能力问题和正常多轮对话继续发送给上游模型。
- 身份回答沿用正常消息的保存、展示、重新加载和模型元数据流程。
- 不依赖上游网关的模型映射或模型自报身份。

## 非目标

- 不验证 AITTCO 或其他网关实际将模型 ID 映射到哪个底层部署。
- 不修改模型选择器、模型 ID、端点路由或上游请求参数。
- 不把所有包含“模型”“GPT”或模型名称的消息都判定为身份问题。
- 不为“这个模型能做什么”“比较两个模型”等能力问题返回固定身份文案。

## 方案

在服务端公共聊天发送入口增加一个小型、纯函数式的模型身份响应模块。发送用户消息后、创建上游 LLM 请求前执行：

1. 从请求上下文读取当前端点、模型 ID 和用户最新消息文本。
2. 使用保守的中文/英文规则判断是否为直接身份询问。
3. 命中时，根据端点解析厂商，根据模型 ID 解析显示名称，构造固定文本。
4. 将固定文本作为普通 assistant 响应交给已有的响应持久化和 SSE/流式适配流程，避免前端出现特殊分支。
5. 未命中时走现有模型调用流程，完全保持现有行为。

身份响应使用如下模板：

```text
我是由 {provider} 训练的大型语言模型 `{model}`。有什么我可以帮您的吗？
```

已知模型的可读名称沿用现有模型目录，例如 `gpt-6-astra` 显示为 `GPT-6 Astra`；没有目录记录时使用原始模型 ID。厂商优先使用端点的 `modelDisplayLabel` 或端点标签，并通过端点别名归一化：OpenAI、Google、Anthropic、xAI。无法识别的自定义端点使用端点显示名称，不编造厂商。

## 身份问题判定

判定器只接受高置信度的直接询问，先规范化大小写、空白和常见标点，再匹配完整短句或明确的问句模式。首批覆盖：

- 中文：`你是什么模型`、`你是哪个模型`、`你是谁`、`当前模型是什么`、`请介绍你的模型身份`。
- English: `what model are you`、`which model are you`、`what are you`、`who are you`，以及带有 `model`/`AI`/`LLM` 的直接身份问句。

不匹配以下内容：

- `这个模型有什么能力`
- `请比较 GPT-6 Astra 和 Claude`
- `用 GPT 写一段代码`
- 讨论历史消息中提到的模型，但没有询问当前助手身份

判定器独立测试中文、英文、标点、前后空白、大小写和否定/能力问题，避免使用宽泛的关键词包含判断。

## 响应与持久化

身份回答不访问上游模型，不产生上游 token 消耗，也不触发上游工具、搜索、文件处理或推理步骤。它仍然使用现有 assistant 消息生命周期：

- 保存用户消息和 assistant 消息。
- 保留当前 conversation、endpoint、model、sender 和 message ID。
- 通过现有流式事件让前端显示回答。
- 标题生成按现有独立配置继续执行，不把身份回答当作特殊标题来源。
- 重新生成身份问题时，根据当次请求的当前模型重新计算，不复用旧回答文本。

如果当前请求没有可解析的端点或模型，身份响应不应猜测，继续走现有请求校验或正常错误处理。

## 数据流

```text
模型选择器
  -> conversation.endpoint + conversation.model
  -> 用户消息请求
  -> 服务端身份问题判定
       -> 命中：解析厂商/显示名 -> 普通 assistant 响应 -> 持久化 + SSE
       -> 未命中：现有 AgentClient -> 上游模型 -> 持久化 + SSE
```

## 测试

增加服务端模块测试，至少覆盖：

- `OpenAI + gpt-6-astra` 返回 OpenAI 和 `GPT-6 Astra`。
- `Anthropic + claude-fable-5-1` 返回 Anthropic 和原始模型 ID。
- Google、xAI 端点及未知自定义端点的厂商解析。
- 中文和英文身份问题命中。
- 能力问题、比较问题、普通包含关键词的消息不命中。
- 未知模型使用原始 ID 作为名称。
- 身份响应路径不调用上游发送函数，并保留响应模型元数据。

在现有客户端/服务端相关测试通过后，使用本地部署验证：选择每个端点的代表模型发送身份问题、普通问题和能力问题，确认身份问题无上游请求，普通问题仍正常流式返回。

## 风险与处理

- 上游端点的真实底层映射仍可能与显示 ID 不同；固定回答只声明 LibreChat 当前选择的配置模型，不声称网关底层实现。
- 自然语言问法很多；判定器保持保守，漏掉边缘表达时让模型正常回答，避免误拦截业务问题。
- 直接响应若绕过公共持久化逻辑会造成前端或历史记录不一致，因此实现必须复用现有 assistant 响应构造和保存路径。
