# Local Source Deployment Design

## Goal

Ensure production deploys the `AigcLee007/chatnew-lib` checkout rather than
upstream LibreChat runtime images. The server must update source with
`git pull --ff-only origin main`, build from that checkout with Docker Compose,
and start the newly built application image.

## Approach

Keep `deploy-compose.yml` as the production overlay. Replace the API service's
upstream registry image with a local `Dockerfile.multi` build targeting
`api-build`. That target compiles the data packages, API, and client assets from
the checked-out source, so application code and frontend output share one
versioned image. Keep MongoDB, Meilisearch, vector DB, RAG, and nginx support
services unchanged unless required for the local image wiring.

The nginx `client` service will use a local image build target that copies the
frontend output generated by `Dockerfile.multi` and serves it with the existing
`client/nginx.conf`. If the multi-stage file does not expose a suitable nginx
target, add a minimal target that copies `/app/client/dist`; do not silently
fall back to the upstream LibreChat image.

## Update flow

Production documentation will prescribe:

```bash
cd /opt/chatnew-lib
git pull --ff-only origin main
docker compose -f deploy-compose.yml config --quiet
docker compose -f deploy-compose.yml build --pull api client
docker compose -f deploy-compose.yml up -d api client
docker compose -f deploy-compose.yml ps
```

The instructions will identify `origin` as the team's repository and include a
check that the Compose model has `build:` entries for application services and
does not use `registry.librechat.ai/danny-avila/librechat-dev-api` for `api`.

## Error handling and verification

Configuration validation must fail before a restart when Compose syntax or
environment interpolation is invalid. A failed build must leave existing
containers running because `up -d` occurs only after a successful build. After
startup, `docker compose ps` and the API logs are used to verify the new image
is running. No secrets are added to git or baked into the image.

## Scope

This change is limited to production Compose wiring and its update
documentation. It does not change provider routing, application behavior, or
third-party support-service images.
