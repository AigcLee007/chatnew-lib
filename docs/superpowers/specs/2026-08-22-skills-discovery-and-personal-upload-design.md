# Skills 发现与个人上传设计

## 1. 背景与目标

当前 Skills 已能在聊天框中通过 `$` 调用，系统也能返回论文写作相关技能。但学生用户面临两个问题：

1. 仅看到名称和截断描述，不知道技能适合什么任务、需要提供什么输入、会产生什么输出。
2. 聊天框和现有管理页面没有形成清晰的个人上传路径，用户不知道如何加入自己的 `SKILL.md`。

本次设计采用方案 C：聊天框负责即时发现和使用，Skills 管理页负责个人 Skill 的上传与维护。个人 Skill 默认仅创建者可见，不提供分享能力。

## 2. 用户体验

### 2.1 聊天框中的 Skill 选择

用户在输入框中键入 `$` 后看到 Skill 弹窗。每项显示：

- 显示名称
- 一句话用途
- 来源标签：`系统提供` 或 `我的 Skill`
- 可选分类标签
- `查看详情` 操作

选择 Skill 仍沿用现有的待发送 Skill 机制，不把 `$skill-name` 作为普通文本插入输入框。

### 2.2 Skill 详情

点击 `查看详情` 打开详情视图或详情抽屉，优先展示可扫描的信息：

- 适用场景
- 能解决的问题
- 所需输入
- 预期输出
- 最小示例
- 完整 Markdown 指令（可展开）

详情提供 `使用此 Skill` 操作。使用后关闭详情并将 Skill 加入当前对话待发送区域。

已有 `SkillDetail` 页面作为完整详情和编辑入口；聊天弹窗只需要提供到详情页的导航或复用一个轻量详情面板，不复制编辑逻辑。

### 2.3 个人 Skill 上传

在 `$` 弹窗底部提供 `上传我的 SKILL.md`，同时在 `/skills` 管理页提供同名主入口。两个入口打开同一个上传对话框，避免维护两套上传逻辑。

上传流程：

1. 选择本地文件或拖放文件。
2. 前端只接受文件名为 `SKILL.md` 的 Markdown 文件，并显示格式要求和大小限制。
3. 发送到现有 Skill 导入接口。
4. 服务端解析 YAML frontmatter，验证名称、描述和正文。
5. 成功后创建个人 Skill，显示成功提示，并刷新 Skill 列表。
6. 从聊天弹窗上传时，成功后自动选中该 Skill；从管理页上传时，进入该 Skill 的详情页。

上传失败时保留对话框，显示服务端可读错误，例如 frontmatter 缺失、名称非法、描述过长或文件超限。不得静默关闭或把原始堆栈展示给用户。

## 3. 管理页

`/skills` 页面继续作为集中管理入口，增加清晰的视图分组：

- `系统 Skills`：可使用、只读。
- `我的 Skills`：当前用户创建或上传的 Skill，可查看、编辑、删除。

个人 Skill 不显示在其他用户的列表中，也不提供分享、公开发布或复制到公共库的按钮。本次不改变系统 Skill 的部署加载机制。

## 4. 权限与数据规则

- 使用：继续使用现有 `SKILLS.USE` 权限。
- 创建/上传：继续使用现有 `SKILLS.CREATE` 权限；没有该权限时隐藏上传入口。
- 编辑/删除：仅 Skill 所有者且具备现有编辑/删除权限时显示操作。
- 读取：服务端列表和详情接口必须按当前用户权限过滤；客户端分组不能作为安全边界。
- 来源：系统 Skill 使用现有部署/系统来源字段；个人 Skill 使用所有者字段和现有资源权限记录。
- 默认可调用：个人 Skill 导入后默认 `userInvocable` 为真，除非其 frontmatter 明确声明为模型自动调用模式。

## 5. 技术方案

### 5.1 前端复用与调整

- `client/src/components/Chat/Input/SkillsCommand.tsx`：增加来源标签、详情入口和底部上传入口；保持现有搜索、分页和待发送逻辑。
- `client/src/components/Skills/dialogs/UploadSkillDialog.tsx`：复用为唯一上传对话框，将文件选择限制为 `.md`，并要求 basename 为 `SKILL.md`。
- `client/src/components/Skills/layouts/SkillsView.tsx` 与 Skills 侧栏：增加系统/我的分组和管理页上传入口。
- `SkillDetail`：补充学生可理解的元信息区；完整正文继续使用现有 Markdown 渲染器。
- `parseSkillMd`：复用 frontmatter 预览和客户端即时错误提示，不取代服务端校验。
- 翻译文件：新增列表来源、详情字段、上传说明和错误文案的中英文键值，至少覆盖 `zh-Hans` 和 `en`。

### 5.2 后端契约

继续复用现有 `POST /api/skills/import` 和 `GET /api/skills`。实现时需要确认并补齐以下服务端约束：

- 导入请求必须绑定当前用户所有者。
- 列表、详情、编辑、删除均执行所有权/权限过滤。
- 单文件模式只允许 `SKILL.md`；非目标文件名或非 Markdown 内容返回明确的 `400`。
- 导入成功后返回标准 `TSkill`，前端据此更新缓存或导航。

如果现有导入接口还要为管理员或其他内部流程保留 zip 能力，应通过明确的服务端调用场景或参数区分，而不是依赖客户端隐藏控件。

### 5.3 数据流

```text
$ 弹窗
  -> 查询可用 Skill 摘要
  -> 查看详情（按 id 查询完整 Skill）
  -> 使用（pendingManualSkills）
  -> 上传 SKILL.md（multipart import）
  -> 返回个人 Skill
  -> 刷新 skills query + 自动选中/导航
```

## 6. 错误处理与边界

- 技能列表加载失败：显示可重试状态，不显示空列表误导用户。
- 技能详情被删除或权限撤销：显示“技能不可用”，清理当前待发送引用。
- 上传过程中：禁用重复提交，显示进度或忙碌状态。
- 上传成功但列表缓存未刷新：以 mutation 返回值更新缓存，并触发列表失效刷新。
- 非法 frontmatter：指出具体字段，不泄露服务器路径或内部异常。
- 无 `SKILLS.CREATE` 权限：聊天框和管理页均不显示上传入口。
- 移动端：详情和上传对话框使用全宽/近全高布局，不能遮挡发送控件。

## 7. 测试与验收标准

### 自动化测试

- Skill 摘要正确显示用途、来源和分类。
- 详情入口加载对应 Skill，使用操作写入当前对话待发送状态。
- 无创建权限时两个上传入口都不渲染。
- 文件名不是 `SKILL.md`、扩展名不是 Markdown、超限文件均在客户端被拒绝。
- 导入错误显示服务端消息，成功后刷新列表并选中/导航。
- 后端拒绝未授权用户读取、编辑、删除他人的个人 Skill。
- 系统 Skill 在个人视图中只读，个人 Skill 在其他用户视图中不可见。

### 手工验收

1. 普通学生输入 `$`，能在不离开聊天的情况下看懂并使用一个论文 Skill。
2. 普通学生能从 `$` 弹窗底部找到上传入口，上传自己的 `SKILL.md` 并立即使用。
3. 刷新页面后个人 Skill 仍在“我的 Skills”中，其他用户账号看不到它。
4. 没有创建权限的账号看不到任何上传入口。
5. 桌面端和移动端均无文本溢出、弹窗遮挡或重复提交问题。

## 8. 非目标

- 本次不实现 Skill 分享、公开发布、团队协作或版本协作。
- 本次不支持 zip、`.skill` 或多文件上传界面。
- 本次不重做 Skill 执行引擎、部署目录加载或 Agent 工具调用协议。
