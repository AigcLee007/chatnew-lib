# 首页右上角主题切换按钮设计

## 背景

项目当前已经支持系统设置、暗色主题和亮色主题，主题选择入口位于设置页的外观区域。此次需求只调整入口位置与首页交互，不更换现有主题视觉系统：在聊天首页右上角增加一个直接切换深浅色的按钮，同时保留设置页的完整主题选择器。

附带截图仅作为布局和交互参考，其中的产品名称、文案和其他界面元素不属于本项目需求。

## 目标与非目标

目标：

- 在聊天首页顶部右侧增加主题切换按钮。
- 点击按钮在深色和浅色之间直接切换。
- 当前主题为系统设置时，按系统当前实际模式反向切换，并保存为明确的深色或浅色主题。
- 保留设置页中的三选一主题下拉框，两个入口共享同一主题状态和持久化逻辑。
- 复用现有语义化主题样式、按钮能力和本地化文案。

非目标：

- 不修改主题颜色、字体、圆角或整体布局。
- 不删除或隐藏设置页的主题选择器。
- 不新增主题类型或改变 `ThemeContext` 的持久化协议。

## 推荐方案

新增独立的紧凑版 `ThemeToggleButton`，放在前端 Appearance 组件目录中。按钮通过现有 `ThemeContext` 读取 `theme` 和 `setTheme`，通过共享的 `isDark` 判断当前实际深浅色，再调用 `setTheme('light')` 或 `setTheme('dark')`。设置页继续使用现有 `ThemeSelector`，避免让一个组件同时承担下拉选择和图标按钮两种职责。

首页 `Chat/Header.tsx` 只负责将按钮放入右侧操作区，不复制主题判断逻辑。按钮在桌面和移动布局中均渲染，并与顶栏已有操作按钮共享间距、层级和响应式行为。

## 交互与视觉

- 浅色模式显示太阳图标，深色模式显示月亮图标；图标按钮使用现有按钮语义样式、hover 状态和键盘 focus 状态。
- 按钮提供本地化 `aria-label` 与 tooltip，使用现有主题切换/主题启用文案键，不在组件中硬编码用户可见文本。
- `system` 模式通过 `isDark(theme)` 解析系统当前实际模式。点击后立即切换到相反的明确模式，因此用户可以从首页直接获得可预测结果。
- 顶栏仍由现有 header 容器控制定位，按钮放在右侧固定操作组中，不改变模型选择器、通知、支持和分享等已有功能。

## 数据流与边界

```text
ThemeContext (theme, setTheme)
        |
        v
ThemeToggleButton -- click --> isDark(theme) ? setTheme('light') : setTheme('dark')
        |
        v
ThemeProvider 应用 CSS 变量、更新 html class、写入 color-theme
```

按钮不直接读写 `localStorage`，也不直接操作 DOM；主题 Provider 继续作为唯一状态和持久化边界。设置页和首页按钮因此会自动保持同步。

## 测试与验证

- 为紧凑按钮增加组件测试：渲染当前模式对应图标和无障碍名称。
- 验证点击深色调用 `setTheme('light')`，点击浅色调用 `setTheme('dark')`。
- 验证系统模式按 `isDark` 的实际结果反向设置明确主题。
- 验证 `Header` 将按钮放入右侧操作区，不影响现有顶栏操作。
- 运行相关客户端单元测试、TypeScript/ESLint 检查以及客户端构建。

## 风险与处理

- 系统模式依赖浏览器的 `matchMedia`，测试中使用已有媒体查询 mock 或局部 mock，避免读取真实系统偏好。
- 右上角操作区已有多个按钮，使用现有 flex 容器和语义间距，避免引入固定定位或遮挡下拉菜单。
- 登录页和分享页已有独立主题入口，本次不改变其现有行为。
